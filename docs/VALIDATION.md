## Реальный HTTP smoke

При работающем `run-dev.sh` выполнена `.venv/bin/python scripts/smoke.py`. Это HTTP-запросы через localhost с cookies и CSRF, а не Django test client. Скрипт зарегистрировал отдельного пользователя, создал портфель, список, порог и стратегию, передал **синтетические** цены и проверил БД и ответы HTML/API.

Фактический итог:

```json
{"http_smoke":"passed","notifications":1,"strategy_trades":1,"cash":"820.000000000","total_pnl":"40.000000000","anonymous_write":403}
```

При начальном капитале 1000 стратегия купила 2 DEMO1 по 90, оставив 820. После цены 110 стоимость акций 220, общая прибыль 40. Повторная цена 90 не создала ни второго уведомления, ни сделки. Logout завершил сессию; последующая анонимная запись API получила 403.

## Наблюдавшиеся неудачные итерации

- Исходные пакеты `tinkoff` и `tinkoff-investments` отсутствовали в реестре; официальный старый Git-тег также требовал недоступный `tinkoff`. Решение — модернизация адаптера, без отключения проверок TLS.
- В первых отдельных тестах общий шаблон ссылался на `portfolio:list`, а маршрут назывался `portfolio:index`: исправлено имя, все HTML-тесты повторно прошли.
- Первые параллельные прогоны подзадач использовали одну тестовую БД и мешали teardown: разнесены по именам, итоговый полный набор выполнен последовательно.
- Промежуточный полный набор во время редактирования шаблона стратегий содержал 1 несовпадение подписи результата: после согласования UI/тестов весь набор прошёл.
- Docker создал родительский каталог данных с чужим владельцем, поэтому первые перенаправления логов туда не сработали. Логи/Beat-state перенесены в пользовательский `.runtime/`, старт повторён; HTTP smoke затем прошёл.
- Для проверки отдельного коммита из архива первая команда была запущена из каталога текущей версии и обнаружила не те тесты/шаблоны. Повтор выполнялся из корня архива; результаты не смешиваются с итоговым набором 82 тестов.

## Непроверенные и внешние условия

Реального `TINKOFF_TOKEN` нет: импорт живого каталога, доступность текущего endpoint и свежесть реальных котировок **не проверены**. Токен следует задать безопасно в окружении; затем отдельно выполнить `add_shares` и обновление. Mock-ответы и DEMO не объявляются live-данными.

Второй независимый AI Coding Agent ещё не выбран/запущен, поэтому полного экспериментального сравнения и его второй ветки нет. Windows/macOS, production deployment и перенос старой заполненной БД до UID-миграции не проверялись. Финальная ветка и сохранение облачной конфигурации описываются по фактическому результату Git/draft-инструмента, а не выводятся из зелёных тестов.
