# Сравнение AI Coding Agents: статус и протокол оценки

## Статус достоверности

По условиям `HOMEWORK.md` требуются **два различных инструмента**, независимые копии исходника и задания №1–4 в каждой. В текущем сеансе фактически использован только OpenAI Codex. Пользователь выбрал «Другой инструмент — укажу»; название и результаты второго инструмента ещё не предоставлены. Подагенты Codex не считаются вторым инструментом.

Поэтому объявлять победителя, выставлять второму агенту оценки или сравнивать затраченное им время сейчас невозможно. Таблица ниже отражает имеющиеся данные и точно показывает недостающие доказательства. Она не выдаётся за законченное выполнение задания №5.

## 2. Единый набор критериев после второго прогона

Оценщик проверяет обе ветки на чистых независимых данных, фиксируя одинаковые команды и входы. Сначала проверяется готовое решение; исправления по результатам оценки записываются как отдельная итерация.

| Область | Проверяемое свидетельство | Правило оценки |
| --- | --- | --- |
| Анализ | Проверка ссылок на исходник, сущностей и потоков | Ошибочные утверждения фиксировать отдельно; не награждать за объём документа |
| Требования | Нумерованный список конкретного исходного поведения | Требование без подтверждения или выданный за требование дефект считать ошибкой |
| Модернизация | Установка в новой среде, миграции, проверки совместимости, сохранённые исходные сценарии | Успешный install без запуска/тестов недостаточен |
| Исправления | Воспроизведение дефекта и регрессия, которая действительно обнаруживает ошибку | Не считать косметический diff исправлением бизнес-дефекта |
| Мониторинг | Два пользователя, список/правило, котировка ниже/выше/равна порогу, повтор котировки | Чужие данные недоступны; для одного события нет повторных уведомлений |
| Портфель | Покупки по разной цене, частичная/полная продажа, оценка, недостаток средств/позиций | Проверить ожидаемые числа, валюту, точность, откат невалидной операции и историю |
| История | Последовательность котировок, повтор/старое время, выбор периода, график и процент | Сверить сохранённые точки и вычисления; нулевой знаменатель/пустой период обработаны явно |
| Стратегии | Условие не выполнено/выполнено, повторная доставка, недостаток ресурсов, отмена | Проверить состояние, виртуальную сделку, журнал, отсутствие дублей и результат |
| Запуск | HTTP-запросы к основным страницам/API и исполненная фоновая задача | PID/open port не заменяют функциональный ответ; mock и live разделены |
| Качество кода | Разделение ответственности, транзакции, валидация, читаемость, объяснимые решения | Привести конкретные фрагменты и последствия, не субъективные прилагательные |
| Автономность | Число вмешательств с причиной | Различать недостающий секрет, уточнение требований и исправление ошибки агента |
| Эффективность | Время, число запусков с ошибками и исправлений по журналу | Определить метрики до замера; не сравнивать общее время одного с временем только генерации другого |
| Ограничения | Наблюдавшиеся сбои, лимиты и оставшиеся проверки | Не приписывать ограничения, которые в эксперименте не проявились |

## 3. Выводы, допустимые сейчас

Codex смог исследовать исходный проект, связать дефекты с конкретными участками кода и продолжить работу после обнаружения недоступных SDK-пакетов. Подготовлены анализ и реализация в отдельной ветке; степень работоспособности подтверждается только фактическими проверками из отчёта. Практическая трудность — восстановление старой интеграции и необходимость отличать контролируемые тесты от работы реального рынка.

Данных о втором инструменте нет. Утверждения «Codex быстрее», «второй инструмент дешевле/автономнее» или выбор лучшего для отдельных задач пока были бы необоснованны. После независимого прогона следует заполнить колонку фактами, приложить ссылки на обе ветки и написать выводы по конкретным различиям в требованиях, исправлениях, проверках, вмешательствах и ограничениях. Нейтральный промпт и процедура независимого запуска приведены в [AGENT_REPORT.md](AGENT_REPORT.md).
