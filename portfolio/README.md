# Виртуальный инвестиционный портфель

1. Авторизованный пользователь создаёт собственные портфели с названием, валютой и неотрицательным начальным виртуальным капиталом. Каждый пользователь видит только свои портфели, позиции и операции.
2. В портфеле можно купить либо продать положительное количество акций (до девяти дробных разрядов) по последней сохранённой положительной котировке. Сделка не обращается к брокеру; цены могут быть устаревшими.
3. Валюта акции должна совпадать с валютой портфеля. Конвертация, кредитование и короткие продажи не поддерживаются.
4. Покупка уменьшает свободные средства и пересчитывает средневзвешенную цену позиции. Продажа увеличивает средства, сохраняет среднюю цену оставшейся позиции и фиксирует реализованную прибыль/убыток. Полная продажа обнуляет позицию.
5. Недостаточные средства/количество, некорректные числа или отсутствие цены отменяют всю операцию. Изменения выполняются атомарно с блокировкой портфеля и позиции (PostgreSQL).
6. Страница показывает текущую стоимость, капитал (средства + акции), реализованный/нереализованный и общий результат, позиции и историю операций (по 50 записей на странице). При отсутствии котировки стоимость и общий результат отмечены неизвестными.
7. Сервис поддерживает повторяемые фоновые запросы с `idempotency_key`: один ключ в рамках портфеля создаёт ровно одну сделку; другой набор параметров с тем же ключом отклоняется. HTTP-форма после успеха перенаправляет на GET; ручное повторное создание без ключа считается отдельной сделкой.
8. Журнал сделок не имеет пользовательских операций изменения/удаления; прямое изменение или удаление экземпляра `Trade` блокируется. Это защита прикладного уровня, не запрет на административные изменения БД.

Архитектура: модели `Portfolio`, `Position`, `Trade`; единый сервис `execute_trade` для HTML и симулятора стратегий; `portfolio_summary` для оценки. `Portfolio.cash` — баланс, `Trade` — журнал движений, `Position` — агрегат остатка. Денежные поля — Decimal с 9 разрядами; итог сделки округляется HALF_UP до 9 разрядов. Публичные HTML-обработчики проверяют владельца до вызова сервиса; доверенные фоновые задачи передают уже выбранный портфель.
