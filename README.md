## Быстрый запуск

Проверено на Linux, Python 3.11, Docker Engine с Compose v2 и `uv`. Docker должен быть запущен; свободны локальные порты 5432, 6379, 8000. На Windows используйте WSL2 + Docker Desktop, на macOS — Docker Desktop и Bash. Эти ОС в данном сеансе не проверялись.

```bash
bash scripts/setup.sh
.venv/bin/python manage.py seed_demo
bash scripts/run-dev.sh
```

Откройте локально порт 8000. Главная страница доступна без входа; регистрация — `/user/registration/`. Портфели, мониторинг и стратегии доступны после входа. Администратор создаётся отдельно: `.venv/bin/python manage.py createsuperuser`.

`setup.sh` устанавливает закреплённые зависимости, запускает PostgreSQL/Redis с проверками здоровья и применяет миграции. Повторный запуск безопасен. `run-dev.sh` запускает Django, Celery worker (solo, 1 процесс) и Beat; Ctrl-C останавливает эти процессы. Логи — `.runtime/`. Данные PostgreSQL — `.dev/postgres/`. Обе директории исключены из Git. Docker-сервисы останавливаются командой `docker compose stop`; данные сохраняются. Для запуска в Windows без WSL используйте эквивалентные команды Python/Celery из скриптов.

`seed_demo` идемпотентно создаёт два **синтетических** инструмента DEMO1/DEMO2 и недельную историю. Реальный рынок и реальные деньги не используются. Новую синтетическую котировку можно подать так:

```bash
.venv/bin/python manage.py demo_price DEMO1 90.123456789
```

Команда разрешает только инструменты, созданные `seed_demo`, сохраняет историю и запускает обработку уведомлений/стратегий. Сначала создайте правило или стратегию через интерфейс. Повторное срабатывание уже исполненного правила исключено.

## Проверки

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test --noinput
# При работающем run-dev.sh: реальные HTTP-запросы, CSRF, БД, правила, сделка и P&L
.venv/bin/python scripts/smoke.py
```

Smoke создаёт отдельного тестового пользователя со случайным паролем и демонстрационные объекты, меняет только синтетическую цену DEMO1. Предназначен для отдельной среды разработки. Тесты используют отдельную `test_investing`; не запускайте несколько полных наборов одновременно против одной тестовой БД. Конкурентные тесты блокировок выполняются на PostgreSQL. SQLite допускается для простых локальных экспериментов (`DB_ENGINE=sqlite`), но не заменяет PostgreSQL для проверки конкурентных финансовых операций.

## Настройки и реальный рынок

Приложение читает переменные процесса. Пример имён — [.env.example](.env.example); `.env` автоматически не загружается. Перед запуском экспортируйте нужные значения в терминале или задайте их в настройках облачной среды.

- `DJANGO_DEBUG` (по умолчанию `1`), `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`.
- `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` — локальный PostgreSQL из Compose подходит по умолчанию.
- `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND` — локальный Redis по умолчанию.
- `TINKOFF_TOKEN` — необязательный токен чтения Invest API. Без него импорт не выполняется, периодическая задача явно сообщает пропуск, локальное приложение полностью доступно.
- `INVEST_API_URL` — HTTPS REST endpoint (по умолчанию `https://invest-public-api.tinkoff.ru/rest`). При необходимости актуальный endpoint задаётся настройкой.

После безопасного предоставления токена выполните `.venv/bin/python manage.py add_shares`. Beat обновляет цены раз в 60 секунд. Дробная часть nano сохраняется; время последней котировки берётся из ответа провайдера. В карточке можно выбрать сохранённую историю или внешние дневные свечи. Реальная интеграция в этом сеансе без токена не проверялась; mock-тесты этого не заменяют.

API `/api/v1/shares/`: публичное чтение, запись только после аутентификации с CSRF для сессий. Фильтры `name`, `ticker`, поиск `search`, сортировка `ordering=name`/`ticker`, пагинация `limit`/`offset`. Для создания обязательны `figi`, `isin`, `name`, `ticker`, `currency`, `uid`; котировки доступны только для чтения. Каталог общий для пользователей; персональными являются списки, портфели и стратегии.

Настройки запуска предназначены для разработки: локальный пароль PostgreSQL и development SECRET_KEY не являются production-конфигурацией. При `DJANGO_DEBUG=0` приложение требует отдельный `DJANGO_SECRET_KEY`. Для production нужны HTTPS, отдельные реквизиты, конфигурация статических файлов и WSGI/ASGI-сервера.

## Обновление зависимостей

Прямые зависимости перечислены в `requirements.in`; точные версии и транзитивные зависимости — в `requirements.txt`. Для осознанного обновления:

```bash
uv pip compile --upgrade requirements.in --python .venv/bin/python -o requirements.txt
uv pip sync --python .venv/bin/python requirements.txt
.venv/bin/python manage.py test --noinput
```

Устаревший SDK, отсутствующий в PyPI, заменён небольшим REST-адаптером со стандартной TLS-проверкой, таймаутом и тестами. Денежные расчёты выполняются `Decimal`, без float. Комиссии, обмен валют, реальные заявки брокеру и исторический бэктест стратегий в этот учебный симулятор не входят.
